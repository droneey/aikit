# Skill calibration

## Design skills: who owns what
- Visual direction (palette, typefaces, layout concept): frontend-design. Treat `ui-ux-pro-max --design-system` output as one input, check it against frontend-design's list of generic defaults, and persist a design system (`--persist`, MASTER.md) only after I confirm.
- UX rules, accessibility, touch targets, forms, navigation and stack guidance: ui-ux-pro-max.
- Motion: Emil Kowalski's skills (apple-design, animate, review-animations, improve-animations, find-animation-opportunities) take precedence over ui-ux-pro-max's animation rules — for example, ease-out for both enter and exit.
- Micro-typography: the typography skill. Use locale-correct quotes: «…» for uk/ru, „…” for pl, “…” for en.
- Accessibility verification: accesslint.
- Slide decks: the Artifact slides type or pptx. Charts: dataviz.
- design-audit: where DESIGN_SYSTEM.md, APP_FLOW.md or PRD.md don't exist, use design-system/*/MASTER.md and PROJECT.md instead.

## Superpowers calibration
- Superpowers skills are tools, not a mandatory first step: use one when it clearly fits; answer questions and make small, well-specified changes directly.
- Brainstorming is for new features or unclear requirements, not for small edits or bug fixes.
- In repositories governed by the droneey constitution, its workflow and testing chapters take precedence over superpowers process skills.
- Skill authoring: skill-creator when it's available. Code review: /code-review.
